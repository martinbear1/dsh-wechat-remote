# DSH 0.1.5-rc.1 文件、会话与传输兼容审查

## 结论与适用范围

DSH 的工作区文件服务、显式交付、轮次过程展示和普通附件上传，可以在插件侧归一化后提供给通用小程序客户端。手机无需复刻 WebUI 的内部组件树，也不应直接依赖 DSH 的日志格式、上传收据或工具名称。当前实现保留原有会话协议，新增可选能力；不支持这些能力的节点继续使用已有对话功能。

本轮发现并在研究分支修正了三个可明确定位的兼容缺口：权限命令缺少新版必填参数；文件改动仍依赖旧的展示字段；文件链接导致普通正文整体进入嵌套文本渲染。过程折叠、普通文件上传及工作区 UI 调整也已落入研究代码。编译和跨端测试通过不等于真机验收完成；本轮没有发布小程序、npm 包、GitHub Release，也没有替换运行中的 Windows 插件或重启云端服务。

审查固定于 DSH `dsh-v0.1.5-rc.1`、提交 `183f08e9c6dde7e36cd2318eaee70b0da08fb35e`。正式基线为小程序 1.7.0、插件 1.7.1、云端 1.2.10。三个研究仓库均使用 `research/agent-resources-20260910`；本轮代码变更涉及插件与小程序，云端无需新增 DSH 专用协议。[^1]

## 已定位的兼容缺口

### 权限切换

Windows 当前安装包的 `commands/execute` 参数解码明确要求 `submittedAttachments` 数组。旧插件只传 `images: []`，会在命令真正执行之前被拒绝。这与“权限未确认”的截图吻合；实际会话没有对应的成功命令事件，并不代表模型忽略了命令。

适配层现在一次调用同时提供 `images: []` 和 `submittedAttachments: []`，覆盖两个参数代际。权限命令仍走原生命令，不作为聊天提示词发送。命令返回之后执行持久化确认并读取原生权限状态，只有目标权限被确认才向客户端报告成功；不通过自动重试重复执行变更。

实际安装包的严格参数解码已复现旧请求失败，并接受修正后的请求。该验证没有实际改变会话权限。最终端到端确认仍需安装研究插件后，在手机与 WebUI 对照切换一次。实现见 `src/dsh-protocol-compat.ts`、`scripts/test-native-file-command-schema.mjs`。

### 最终回复长按选字

交付链接接入后，Markdown 的顶层拆分仍只检查网页链接。只有工作区文件链接、没有网页链接的长回复，会把标题、正文、表格和文件列表合成一个嵌套 `<text>` 块；这改变了原来的富文本选择路径，也会丢失部分块级样式。

已把工作区链接加入相同的顶层拆分规则：只有真正含链接的片段使用可点击文本，其余正文和表格继续采用原来的可选富文本。嵌套文本各层明确开启 `user-select`，并保留 `selectable` 兼容设置；普通正文不绑定点击或长按处理器，文件链接和网页链接各自保留精准点击。没有用“整条复制”弹窗替代自由选字。

新增回归用例在修复前失败、修复后通过，验证长正文、文件列表、表格、引用分段及选择属性。该测试能证明渲染分支修复，不能代替 iOS/Android 原生长按选区与拖动手柄的真机验证。已有会话重新渲染即可应用，无需重新生成答案。实现见小程序 `utils/format.js`、`tests/message-selection.test.js`。

### 文件改动卡片缺失

新版 WebUI 的“本轮文件改动”来自成功的文件写入/编辑工具事实，不等价于模型显式交付的文件。只依赖旧产物展示字段，无法覆盖新版事件形态。新版 `surfaceOp` 还位于事件顶层；替换或非 append 的记录不能重复当成新的输出。

插件已基于原生 write、edit、str_replace_editor 调用及成功结果生成可选 `changedFiles`。只解析明确的参数结构和匹配结果，不从 shell 输出、阅读路径或模型文字猜测文件改动。历史恢复、实时事件和分页都承接相同语义，小程序在最终回复后恢复文件改动入口。[^3]

## 过程折叠

### WebUI 的实际时机

`ChatNodeSeat.tsx` 的可折叠窗口要求启用紧凑会话展示、存在过程定义和最终回复锚点、轮次匹配、轮次已经关闭，并且历史完整。它不是把任务过程中每个刚完成的工具逐条塞进同一个已折叠过程组。单个工具卡片自身的展开/收起，和整轮过程折叠是两件事。[^4]

`turn-process.ts` 用最后一个步骤中的最终回复确定答案位置；过程消息数不把纯 reasoning 当成一条正文消息，子代理调用也单独计数。这解释了为什么某轮有 48 个步骤和 48 条 assistant message，而 WebUI 显示的是“55 次工具调用 · 27 条消息”。[^5]

### 通用投影与保护规则

新增 `agent.activity.v1` 携带轮次、最终回复锚点、过程范围、工具/消息/子代理计数，以及可选文件改动。小程序只消费这些通用字段，不解析 DSH 工具名。插件负责从 DSH 原生事实转换；其他 Agent 可独立提供相同协议。

当前小程序规则比原生“轮次关闭”更保守：只对完整且成功结束、已有最终回复的轮次默认收起。未加载完整边界、失败/取消、未结束工具、错误行、用户消息和待确认事项不隐藏。用户可展开，原始轨迹仍完整保留。

折叠发生在 60 行渲染窗口裁剪之前。否则超过 60 行的真实长任务会先丢掉过程开始位置，导致折叠消失或计数错误。当前用例覆盖 110 行长轮次：收起只渲染摘要与最终答案，展开恢复原始可见行，不预渲染被折叠的所有 Markdown。

## 文件、交付物与输入附件

### 三种不同概念

| 概念 | 事实来源 | 示例与展示 |
|---|---|---|
| 本轮文件改动 | 原生成功写入/编辑事实 | 生成脚本、校验脚本；最终回复后的可折叠入口 |
| 显式交付文件 | `deliverables/presented` | Excel、PPT、PDF 等正式交付；回复链接/文件卡片 |
| 工作区文件 | 当前工作区目录与文件服务 | 可能早已存在，与本轮是否改动无必然关系 |

运行 Python 或 shell 生成 Excel，不一定产生与 Excel 路径一一对应的原生 write 工具调用。因此“本轮文件改动”不能冒充“本轮生成的所有文件”；完整生成物应由显式交付或实际工作区浏览补充。显式交付也可以引用之前就存在的文件。[^3]

### 工作区入口与预览

入口改为对话/轨迹胶囊旁的独立圆形文件按钮，而不是第三个分段标签。它不占用微信原生右上角胶囊。点击正文文件仍进入同一右侧面板并聚焦文件，避免增加一套平行操作。

面板使用既有全局玻璃表面、边框、阴影和主题色；左侧圆角、顶部胶囊避让、底部安全区统一处理。目录列表与文本预览分开滚动，底部保留选中文件及预览/转发操作。Markdown 显示为安全富文本而非裸标记，代码保留换行；HTML 作为文本，不执行其中脚本，Markdown 外链图片不会自动加载。

手机预览不可能与桌面 WebUI 完全等价。微信原生文档查看器列出的格式包括 doc/docx、xls/xlsx、ppt/pptx、pdf，Markdown 不在其中；图片使用原生图片查看，Markdown/普通文本由小程序展示。未知格式保留转发入口，不伪造“已支持预览”。大文本超过当前 256 KiB 展示上限时提示转发查看。[^6]

### 普通文件输入

新能力 `agent.inputs.v1` 声明是否支持文件、文件数及大小限制。当前实现每条最多 6 个普通文件、单个最多 10 MiB，通过微信聊天文件选择器获取用户主动选择的临时文件。现有相册/拍照图片入口继续保留。

插件接收内容后调用 DSH 原生 `fileUploads/upload`，把原生收据封装成短时、会话绑定且有 MAC 校验的令牌。提示词提交只携带该令牌，由插件还原成原生 receipt；手机不需要理解 receipt 生命周期。节点/会话切换、取消、超限、篡改和重启失效均不能继续发送到另一个会话。[^7]

当前原生文件上传服务面向普通根会话；不据此宣布所有子代理支持文件附件。能力探测失败时隐藏文件入口。通用令牌对客户端是“不解释的标识”，并非秘密 URL；真正访问控制仍由插件、身份认证和原生上传服务承担。

微信聊天文件选择器不等于手机整个 Files/Downloads 文件系统选择器。本轮没有实现不存在的通用 `wx.chooseFile` 接口，也没有把桌面专用保存能力写成 iOS/Android 已支持。手机文件若不在微信聊天内，目前需先通过系统/微信正常分享方式放入可选择的位置；后续扩展必须基于真实可用的官方入口。[^6]

## 真实测试记录与传输路径

### 对话事实

对 Windows 最近交付测试会话进行了只读核对：返回 287 条事件，`hasMore=false`；1 个完整轮次、48 个步骤、48 条 assistant message、55 次工具调用和 55 次工具结果。新的过程投影得出 55 次工具调用、27 条消息、0 个子代理，与 WebUI 截图一致。

成功文件改动有 5 项：`fetch_libs.py`、`make_deliverables.py`、`validate.py`、`com_check_excel.ps1`、`com_check2.ps1`。显式交付有 6 项：销售报表.xlsx、简报.pptx、报告.pdf、销售图表.png、说明.md、资料包.zip。二者是不同集合，并非丢了 6 个文件。

这些记录确认了事件投影和归属，不构成手机已成功下载、预览或转发的服务器证明。没有为此次核对调用模型、创建会话或修改权限。私有会话 ID、令牌及配对信息不进入本报告。

### 数据路径

| 数据 | 加密局域网 | 公网 |
|---|---|---|
| 聊天流、权限、队列、目录元数据 | 手机与节点直连 | 经中继 WebSocket 传送端到端加密消息 |
| 工作区文件下载 | 节点不可变快照，192 KiB 分块读取 | 节点上传加密临时对象到 OSS，手机直接下载并解密；中继只承载描述信息 |
| 新普通文件输入 | 手机读取临时文件，经加密直连提交 | 手机加密后直传 OSS，节点下载并解密；命令传递对象描述与令牌 |
| 压缩历史 | 小包内联；大包可经 OSS | 小包内联；大包经 OSS |

压缩历史的内联阈值为 96 KiB。历史预热会独立发生，因此“当前手机走局域网”并不意味着该节点绝对没有 OSS 活动。文件列表不会自动上传整个工作区，实际文件按需获取；公网大文件失败也不会悄悄回退成服务器转发的大段 base64。

本轮还修复了安全局域网图片路径的判断：安全局域网复用公网传输对象的代码结构，不能仅凭对象类型认定需要 OSS。现按真实 `local`/资源交付路径决定，直连图片不再因此误走 OSS。

### 云端可证明和不可证明的范围

在 17:20–18:30（北京时间）的对应主机窗口内，只读对象记录显示 1 个由 Agent 准备完成的 artifact，对象密文 79,346 字节；2 个历史对象合计密文 205,395 字节。该窗口未见客户端上传附件对象。对象密文大小与某个文件大小接近，不足以断定就是那个文件；现有记录没有明文文件名与会话关联。

当前没有按会话、文件和路由划分的完整字节账本，所以不能给出“这一轮精确多少字节经过 ECS、多少经过 OSS”的结算级数字。月度账户汇总也不能当作单次会话流量。OSS 避免大文件占用中继数据转发，但并不等于免费或不计公网额度。

云端独立服务在核对时正常运行。服务器磁盘约 86% 已用，剩余约 5.4 GB；它是后续容量维护事项，本轮没有删除日志、缓存或其他项目文件。过期未完成上传记录也没有擅自清理。

## 隐藏兼容风险与边界

| 边界 | 当前处理 | 未作出的承诺 |
|---|---|---|
| V3 日志与迁移 | 经原生 Session 服务读取；保留业务序号语义 | 不支持把升级日志直接交给旧 DSH 降级读取 |
| SessionHandle、锁、显式 Agent | 插件通过宿主服务与明确地址访问 | 不通过复制日志或新建后台进程绕过锁 |
| 新版实时流 | 已有研究适配分别接入实时 assistant stream 与持久事件，处理 revision、attempt、重连基线与废弃重试 | 历史日志不能还原当时手机每个屏幕刷新帧 |
| 非 append 事件 | 过滤替换式记录，不重复追加最终消息/文件改动 | 不把所有历史投影事件都视为新增聊天行 |
| minimal/persistent shell | 文件改动仅取可靠 typed write/edit，交付走显式文件协议 | 不从任意 shell 输出猜测完整生成物 |
| 工作区外路径、本地图片 | 手机文件服务继续规范路径、校验作用域及版本 | 不照搬 WebUI 读取工作区外截图的宽松体验 |
| 文件变化竞态 | 下载绑定版本与不可变快照，取消/释放受控 | 不把变动中的文件分块拼成混合版本 |
| 子代理输入与队列 | 会话地址解析区分根/子节点，能力按实际作用域返回 | 不把可继续聊天等同于原生文件上传可用 |
| 模型目录与统计 | 读取实际模型目录；可选字段缺失则隐藏 | 不把新默认模型强制覆盖已选模型 |
| read_image/PTC 图片 | 保留已知图片路径，未知结构安全退化 | 尚未完成全部嵌套 PTC 图片到通用资源协议的扩展 |
| Web 插件 Slot | 手机布局与 Slot 解耦，设置插件注册单独测试 | 不宣称所有第三方 Web 插件面板都能投到手机 |
| 分享/预览 | 系统选择器与系统文档预览，失败有提示 | 不静默发送给联系人，不声称知道接收方已读 |

V3 的单向迁移与 Session 生命周期变更是升级/降级时必须单独检查的风险，而不是手机渲染优化能够解决的问题。官方明确新版会话不支持旧版本降级读取。[^1][^8]

## 通用协议职责

| 层 | 应承担 | 不应承担 |
|---|---|---|
| 小程序 | 能力探测、文件/过程的通用交互、预览与选择、节点切换隔离 | DSH 工具参数推断、DSH 日志迁移、原生 receipt 规则 |
| Agent 插件 | 原生事实转换、路径授权、内容读取、上传收据映射、旧版参数兼容 | 随意篡改原始会话、伪造计数或已完成状态 |
| 云端 | 身份、端到端加密转发、短期对象授权、额度/过期管理 | 理解模型工具名、解析用户文件明文、判断“模型是否真的完成” |

`agent.resources.v1`、`agent.activity.v1`、`agent.inputs.v1` 独立协商。将来 Claude Code 或 Codex 适配器可只提供其中一部分；缺少文件输入不影响已有文件浏览，缺少过程统计不影响对话，未知 schema 不触发隐藏内容。协议留有可选字段不意味着未来节点已完成适配，需要对应真实数据和契约测试。
