# 1.7.5 问答/审批完成事件修复

本版统一根插件、npm 安装工具、GitHub v1.7.5。基于 main f290bc2；不覆盖历史 1.7.3/1.7.4（内置 1.7.2）的不可变包。保留一行安装放行策略、慢启动支持、既有安全归档审计与失败回退。

## 原因

DSH 0.1.5-rc.1 Gateway 的 receiveRemoteEventResult 先移除 responding delivery，然后 finishRemoteEvent 向剩余客户端广播 cancel。应答源自己不会收到 cancel。适配层先前只在 cancel 时清 pending，所以小程序提交已真正消费、原生工具已完成，适配层仍保留并向新连接重放旧请求。问答/审批真实记录均已确认，不修改磁盘历史进行补救。

## 修正

- 成功原生 result receipt 与 cancel 共用幂等 settlePending；所有 mux 都收到现有 resolved 合同，新增可选 approvalRpcId 关联本次交付，不改旧 approvalId。
- 同交付只能有一个正在发送的响应；重复帧不覆盖对象锁。失败保留请求以供手动重试，旧 upstream 的迟到回执不能清除替代交付。
- resolved 只表示不再等待此次用户输入，不表示工具执行成功；拒绝与取消结果原样传递，不更改审批策略。
- 小程序配套 trial.7 严格消费已确认回执/完成事件，并将真实问答工具结果按原顺序做只读折叠展示。已发布小程序仍能消费原有 resolved。

## 验证

插件构建、verify、全套 npm test；新增测试不再人为补发 responder cancel，覆盖双端通知、重连不重放、失败重试、并发、用户取消、他端完成、源切换竞态。小程序跨端测试串联运行适配器与客户端生命周期。只读核对 Mac 0.1.5-rc.1 上已完成问答/审批的持久历史顺序。
