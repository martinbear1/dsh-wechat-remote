# 小程序首次打开 · 初始化（登录）页设计交代

> 给小程序侧开发者：目前工程**没有独立初始化页**（未配置时主页面只显示错误态，
> 用户在设置页扫码）。下面是建议的完整设计，供实现参考。UI 遵守你方的
> DESIGN.md「Refined Air」规范（胶囊避让 / 安全区 / 色彩令牌 / 图标体系）。

## 判定逻辑

启动时（app.js / store.bootstrap）：

```js
const cfg = store.loadConfig()
const configured = !!(cfg.baseUrl || cfg.funnelUrl)
```

- 未配置 → 进**初始化页**（onboarding）
- 已配置 → 走现有 connect 流程；连接失败时主页面错误横幅 + 设置入口（现状保留）
- 已配置但 baseUrl 含 `:3090`（老插件时代）→ 初始化页提示「检测到旧版本配置，
  请重新扫码配对」或自动替换为 `:3092` 重连

## 页面结构（三段式，单页滚动或三步向导）

### ① 这是什么（首屏）

- 品牌 logo（`images/logo.png`）+ 一句话：「在微信里实时控制你电脑上的 DeepSeek Harness」
- 三个特性 chip：微信身份绑定 / 扫码即用 / 局域网直连（公网预留）
- 主按钮：「开始设置」

### ② 电脑端准备（引导屏，最显眼的安装指引）

按序 3 步，每步带状态描述（完成与否由用户自行确认）：

1. **安装插件**：可复制命令卡片
   `dsh plugin --profile web add github:martinbear1/dsh-wechat-remote#v1.0.1`
   （附小字：需已装 git；若提示 pnpm 不存在，先执行 `npm install -g pnpm`）
2. **重启 DSH**：退出并重新运行 `dsh web`（小字：必须重启才生效，
   因为 DSH 插件在启动时加载；重启不会丢失会话记录）
3. **打开二维码**：浏览器开 `http://127.0.0.1:3080` → 侧边栏底部点
   「**微信连接**」→ 弹出配对二维码

### ③ 扫码配对（动作屏）

- 主按钮「**扫码配对**」→ `wx.scanCode` → 现有 `parseQRPayload` →
   `pair.claimWechat(payload, base)` → `store.saveConfig` → `store.connect` →
   跳转主页（现有 settings.js:139-186 逻辑可直接复用）
- 副按钮「**手动输入配对码**」（8 位，大小写不敏感）：**模拟器没有摄像头，
  这是开发期硬需求** —— 输入后构造与 QR 载荷相同的对象走同一条 claim 流程；
  手动输入时 host 用电脑局域网 IP（默认提供上次成功的，可改）
- 兜底入口「手动配置」：baseUrl + token 整串输入（复用 settings 手动配置逻辑）

### 错误态文案（逐条给可读提示 + 重试）

| 场景 | 文案 |
|---|---|
| 二维码内容无法识别 | 请扫描电脑端「微信连接」弹窗里的二维码，而不是其他码 |
| 配对码过期/已被使用 | 二维码 15 分钟有效且一次性，请回电脑刷新弹窗后重扫 |
| 微信身份解析失败（401） | 电脑需要能访问 api.weixin.qq.com；或先不配置 gate-wechat.json 走开发态 |
| 网络不可达 | 手机与电脑需同一 Wi-Fi；确认电脑防火墙未拦截（一般无需手动开墙） |
| 扫码取消 | 已取消，可重试 |

### 成功态

toast「配对成功 ✓（微信身份已绑定）」→ `wx.reLaunch` 到主页面 → 自动连接
（`store.connect(cfg)` 已包含）。同时**立刻执行一次启动复核**（按适配清单
「必改 1」第 3 点），完成首次 token 轮换闭环。

## 与设置页的关系

- 设置页保留「扫码配对 / 身份复核 / 手动配置」三个入口（现状不动），
  初始化页只是把它们前置到首次使用路径上
- 「身份复核」按钮语义升级为「校验并轮换凭证」（适配清单必改 1）

## 开发期注意

- 模拟器：域名校验关闭（工程已配置 urlCheck: false）；用「手动输入配对码」路径
- 真机：同一 Wi-Fi；开发者工具扫码预览；配对走真实摄像头
- 配对码在电脑端两处可见：侧边栏弹窗、`http://127.0.0.1:3093/pair` 页面
