# 安装与更新

## 新装

在 DSH 的 **插件 → 添加插件** 中输入：

```text
dsh-wechat-remote@1.7.16
```

本版为 `1.7.16`；也可使用 `dsh-wechat-remote@latest` 选择当前正式版，不会自动选中验收用的预览版。新包可能受安装环境的等待策略影响，请核对实际安装版本，并按原生管理器的提示处理。

Web 和 Desktop 使用相同包名。安装并启用后，打开 **设置 → 微信连接** 或本插件详情，扫码配对。

安装后的提示只核对当前端。已生效时无需重启；新版已安装但仍运行旧版时，请等待任务结束，Desktop 选择「应用 → 退出」后重新打开，Web 用原启动方式重启实际服务。仅关闭窗口、关闭标签页或刷新网页不等于重启服务，无需重新配对。

停留在插件详情页时，如新版尚待重启，插件更新区域也会显示说明，无需先返回列表找提示。插件内一键更新完成且仍需手动重启时，会提醒一次；已自动重启并生效的更新继续显示完成状态，不再要求重启。关闭提醒不影响更新结果或插件使用。

如果组件未就绪或存在安装错误，请查看原生安装详情；提示不会隐藏原生报错，也不保证重启可以解决所有安装错误。Web 和 Desktop 各自检查更新，不再提供另一端联动更新。

## 已有用户升级

打开已有插件的检查更新，按页面提示安装。无需先卸载，不需要重新配对。

以下旧版升级说明针对插件 `1.7.13`；更早的安装请按实际提示核对，不要混用不同安装方式。

### Web 旧版提示“请回到 DSH 原生插件管理页更新”

通过 DSH 插件管理器安装的 Web 插件 `1.7.13`，其旧更新按钮不能直接完成这次升级。自 `1.7.14` 起提供命令行保底替换，无需卸载、手动下载或填写安装包路径。

在同一系统用户下，结束任务并按原方式正常停止 Web，再运行：

```sh
npx -y dsh-wechat-remote@1.7.16
```

安装器替换 Web 原有插件，不添加第二份，不更新 DSH 本体或 Desktop。成功后尝试启动 Web；后台服务用户可加 `--no-start`，由原服务恢复启动。无需重新配对。请确认获取到 `1.7.14` 或更高的正式版本。

升级到本版并重启后，具有原生插件管理器的 Web 可以继续使用插件内检查更新。

如提示待重启，请结束当前任务后正常重启对应 DSH。Desktop 完全退出并重新打开；Web 重启服务，仅刷新网页不会加载新的服务端插件。

## 重复添加与旧安装

DSH 可能对已安装的相同包名提示“已安装”，这不代表已经更新。可使用插件内更新的安装继续使用该入口；遇到上述 Web 旧版提示时，使用本版命令行保底方式，不要反复添加。

新安装器识别并替换现有包，保留早期命令行安装的原包名，不叠加另一份。若此前已经出现两个条目，先保留配置、配对和会话，核对安装记录后再处理，不要直接删除数据目录。

从旧 `1.7.14` 首次升级时，旧插件可能未能释放连接端口。即使新版本已经安装，连接也可能暂时不可用或反复重连。请等待任务结束后完整退出并重新启动对应 DSH，无需卸载、重新配对或反复安装；这次迁移不能保证热更新。后续升级是否需要重启，仍以原生管理器和插件的实际提示为准。

## Web 命令行安装器

没有图形插件管理器或需保底替换时，在与 Web DSH 相同的系统用户及环境下运行上面的 `npx` 命令。需要 Node.js 22.13 或更高版本，无需另装 pnpm 或 Git。Windows CMD / PowerShell 可用 `npx.cmd -y dsh-wechat-remote@1.7.16`，无需更改脚本执行策略。

运行前结束任务，通过原启动方式正常停止 Web；后台服务需先暂停自动重启。安装器保留原配置、配对和会话，不升级 DSH 本体，也不强停任务。成功后尝试启动 Web；后台服务可加 `--no-start`，确认安装完成后由原服务启动，避免重复启动。若启动失败，请查看安装日志；启动失败不代表已安装插件自动回退，不要删除数据。

默认使用 `web` 配置及原数据目录。自定义目录需保留相同的 `DSH_HOME`，或使用 `--home "数据目录"`；其他配置使用 `--profile 配置名称`。存在多份 DSH 且无法确定时，可用 `--dsh-cli "DSH的lib/bin.js路径"` 明确选择。WSL、容器和其他系统用户需在对应环境执行，不能跨环境替换。

停止 Web 后可用 `--repair` 主动重装，不会自动降级。结果不明时先核对记录，勿重复安装。本命令不安装、更新或停止 Desktop，也不支持 `--profile desktop`。
