# 1.7.7 候选追加：宿主用量模块定位

## 基线与范围

- 正式 `v1.7.6`（提交 `a6ebbc2`）是候选分支的祖先；候选从发布后的 main `527a98a` 接出，追加在原候选 `381d162` 之后，不合入 ClawBot 研究代码。
- 用量修复只改插件 `turn-presentation` 的宿主模块定位。实机验收另发现同版本新内容重装未替换的问题，一并修正共享 `install-profile` 的本地包标识。小程序、云服务、DSH 本体和三端接口协议不变；npm 使用同一安装核心，不新增独立修复脚本。
- 不发布、不推进 main、不改 npm/GitHub latest、不部署或重启云端。旧候选和旧候选标签保留。

## 因果与原始证据

1. Mac 和 Ubuntu 实际 DSH CLI 同为 `0.1.5-rc.1`，已安装的官方统计及相关核心模块同为 `0.1.5-rc.2`；插件均为旧候选 `1.7.7`。不是 Mac 单独使用了 Alpha。
2. Mac 普通命令启动时 `process.argv[1]` 为 `/usr/local/bin/dsh`，它指向实际的 DSH `lib/bin.js`；Ubuntu 测试后台直接从真实 `lib/bin.js` 启动。
3. 旧 `createRequire(process.argv[1])` 以快捷文件目录寻找公开包入口，导致 Mac 的 `@deepseek-ai/dsh-token-meter/client` 加载失败。旧代码把可选模块缺失转为 undefined，历史仍可读，但单轮 facet 缺少 usage。
4. 小程序仅在该回复有 usage 数值时显示用量图标，timing 独立展示；会话总用量走原生 tokenUsage 投影，故截图表现为“时钟和会话总统计正常，单轮用量按钮消失”。
5. 用户 `nihao` 会话第 7 轮原生事件含总量 9637、输出 699、未缓存输入 234、缓存读取 8704。相同事件交给正确宿主的官方函数，能完整生成单轮用量；数据未丢失。
6. 既有安装/更新实机测试主要验证生命周期和原生会话可读，恢复时直接使用真实 CLI 路径，且清理后未带真实模型用量。这一组合掩盖了普通快捷命令启动的读取缺陷，必须补充回归，不能声称旧验收已覆盖。

## 修复原则

- 仅先 `realpathSync` 规范化当前宿主入口，再按 Node 标准解析加载其公开 `client` 导出。
- 不搜索 PATH 中另一套 DSH、不导入插件开发依赖中的统计版本、不硬编码 npm/NPX 缓存位置、不解析日志或猜测 token，不改写 DSH 本体。
- 保留官方 `deriveTurnTokenUsage` 的完整轮次输入，以及发生在传输压缩之前的计算时序。旧宿主真正没有该公开能力时仍不编造数值。
- 每个插件模块生命周期只解析一次，复用原有 Promise 缓存；没有新增后台进程、扫描器、定时器、请求或常驻服务。

## 相邻审阅

| 边界 | 结果 |
| --- | --- |
| `installedDshVersion` 宿主版本读取 | 已先解析实际入口；PATH 仅为版本识别兼容回退，不用于本次用量模块加载 |
| `install-control`、`update-service` | 已对当前入口使用 realpath，更新绑定实际宿主，不依赖终端当前目录 |
| 安装器 `dsh-discovery` | 验证 canonical CLI 与包 manifest 的 bin 一致；运行实例握手优先于其他已安装版本 |
| `resolveInstallRuntime` | 读取本安装事务所属包的 pnpm，并校验实际路径；它不是 DSH 业务数据来源 |
| 历史、会话投影、时序 | 读取原生 session.history / 宿主服务；已有 V3 紧凑事件支持，未从页面文案或日志反推数据 |
| 小程序用量与用时 | 消费按 messageId 关联的可选 facet，缺失与 0 区分；不推断本机安装路径，不自行补造 token |
| 云端 | 不参与解密和计算本轮用量；本次不需要改接口或部署 |

本轮未发现第二处同样的业务模块快捷路径解析错误；这是有范围的审阅结论，不代表所有未来 DSH 版本和任意启动器都已实测。

## 验收中发现的同版本包复用

- 首次把修正用量的同版候选装到 Mac 后，安装事务成功、版本和锁文件完整性均正确，但普通命令重启仍没有 usage。逐文件核对发现已安装代码仍是旧实现，不能以安装器成功提示代替功能验收。
- 原安装核心把包复制成固定 `harness-remote-1.7.7.tgz`。用 pnpm 11.22.0 的原生 hoisted 安装做最小独立复现：同路径、同版本、不同内容再次 add，锁文件更新但旧文件保留。Windows 和 Mac 均复现。改成内容摘要标识的本地包路径后，两端均正确替换，重复同内容仍正确。
- 共享安装核心现在使用 `harness-remote-<version>-<sha256>.tgz`，仍由目标 DSH 的官方 plugin add 完成解析和注册。不强制重建整个依赖树、不清空用户缓存、不改写锁文件、不修改其他插件来源。SHA 只用于安装事务，没有会话运行期开销。
- 这解释的是同版本不同候选内容的复用问题，不能据此称所有正常的 1.7.6 → 1.7.7 更新都曾失败，也不能宣称自动修复任意已损坏文件。已发布版本仍不可覆盖重发。
- 旧固定文件名分支已替换，不保留第二套安装实现；新增测试放在开发目录，未包含于发布制品。运行包没有加入测试脚本或依赖。

## 回归与验收

- 新增独立进程测试：全局与 NPX 目录布局、真实入口、POSIX 相对/多级软链接、保留主入口软链接模式、Windows 目录联接、中文/空格路径、不同 cwd、启动目录中存在另一统计包、缺少公开导出、缺少模块、无主入口，以及并发/后续请求的缓存一致性。
- Mac 和 Ubuntu 上旧实现均在链接启动测试失败，并可能误取启动目录旁的统计包；替换临时测试副本为新实现后通过。没有修改测试机 DSH 本体。
- Windows 构建、插件全量测试和 verify 通过；小程序 383 项单元、20 项公网与 21 项跨端测试通过。跨端测试明确指向本候选，未使用其他插件工作树。
- 最终完整 npm 候选包在 Mac 执行同版本修复安装、自动重启成功；安装后的 `turn-presentation.js` 和 `install-profile.js` 与归档逐字节相符。
- 再次确认无运行任务后，正常停止并使用 `/usr/local/bin/dsh web --no-open` 启动（实际进程 `node /usr/local/bin/dsh web --no-open`，PID 70634）。原 `nihao` 会话第 4—7 轮均有 usage，与同一历史交给当前宿主官方函数的结果完全一致；第 7 轮总量 9637、输出 699、未缓存输入 234、缓存读取 8704、推理 178。
- 凭据、节点身份和配对在两次重启前后摘要一致，4 个原会话 ID 不变；没有发起模型请求或修改会话消息。Mac 已重新打开带本机授权的 WebUI。
- 将实际收到的 facet 输入未修改的小程序展示函数，第 4—7 轮各生成 7 行用量和 3 行用时，满足原有图标显示条件。手机实际图标仍需用户重新进入会话复核，不以接口验收冒充真机 UI 点击。
- 最终修正后再次通过插件全量 npm test、verify 和构建。新增文件名规则的最小原生安装实测在 Windows/Mac 完成；原候选四机首装/更新记录继续保留，不冒充四机都重新跑过这次最终字节。
