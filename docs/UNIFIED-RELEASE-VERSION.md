# 插件端统一版本规则（2026-09-14）

插件端是一个产品发布单元，包含安装到 DSH 的插件包、npm 一行命令安装工具和 GitHub Release。对外使用一条版本线，不能因只修改安装工具而继续另起“安装器版本”发布线。

## 后续发布必须满足

1. 每次发布统一递增一个版本 `X.Y.Z`。根目录插件 package.json、插件内部上报版本、安装工具 package.json / lockfile、随包插件归档、release 元数据均对应这个版本。
2. GitHub 只创建一个 `vX.Y.Z` 标签和 Release，标题仅为 `vX.Y.Z`。同一个 Release 附上插件归档与 npm 安装工具归档；npm `dsh-wechat-remote@X.Y.Z` 内置相同版本插件。稳定发布确认后更新 Latest / npm latest。
3. 只修改安装工具也推进整个插件端版本；插件没有功能变化可在正文中说明，不再维持独立的对外插件版本号。
4. 发布正文简洁描述实际变化，区分“安装与升级优化”“插件功能修复”等即可，不把组件名放在列表标题上。只声明真实验证的系统和功能。
5. 版本相同不等于行为兼容。更新检测继续使用插件归档版本、摘要、能力检查及服务端发布清单，不依据 GitHub 标题猜测版本或兼容性。
6. 发布前核对根目录与 installer 版本、两个 lockfile、插件实际归档 package.json、安装工具内 assets/plugin.tgz、assets/release.json、归档摘要；发布后从 npm 与 GitHub 回读验收。只改标题不能代替此核验。

## 已经发布的历史版本

`1.7.3`、`1.7.4` 的 npm 包已不可覆盖，里面的插件确实仍是 `1.7.2`。因此不能声称这些既有文件已经变成统一版本，也不能替换同版本 npm 内容或删除旧归档来掩盖差异。

- GitHub 公布版本标题统一为 `v1.7.3`、`v1.7.4`，正文保留当时只更新安装工具、内置插件仍为 `1.7.2` 的真实说明。
- 已分发的 `installer-v1.7.3`、`installer-v1.7.4` 标签和附件地址保留，避免使历史链接失效；不再另外创建同版本重复 Release。
- 截至本规则记录时，实际发布包仍为插件 `1.7.2` / npm 工具 `1.7.4`。下一次正式发布应从未占用的 `1.7.5` 起完成包内版本同步，而不是覆盖现有 `1.7.4`。
- 列表顶部的旧 `1.6.0-rc.3` / `rc.4` 是维护者可见的草稿，不是额外正式发布。保留其草稿状态和历史材料，不因调整列表而删除。

本次只整理公开标题、记录后续统一规则，不重新发布 npm、不改变现有归档、配对身份或更新清单；GitHub Latest 在统一包正式发布前仍保持现有插件 `v1.7.2`。
