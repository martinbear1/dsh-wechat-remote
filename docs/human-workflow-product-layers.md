# 职业预设和群工作流的产品分层

本文件落实本轮用户补充的使用路径，区分 DSH 原生预设、具体工作实例、skill、工具和群任务。目标不是让用户手写提示词、工具协议或配置文件，而是由插件帮助用户找到或生成合适的预设，在主人确认后，通过宿主原生机制使用。教师只是例子，不是核心代码的职业限制。

当前新增代码完成的是部分群任务基础能力和任务规则包，不是完整的职业预设创建器。本文明确哪些已经实现，哪些仍需接续开发，避免把研发目标当成产品已经可用。

## 用户从创建预设到开始工作的路径

1. 用户选择现成起点，或说明职业、目标和工作习惯。创建助手询问必要信息，生成职业预设草稿；不要求用户理解 JSON、插件命名或 skill 文件。
2. 主人预览预设的工作方法、所需工具、权限和资料处理范围，确认后保存为节点上的原生预设。不悄悄替换用户原预设或全局默认项，不自动下载或执行任意第三方插件。
3. 用户选择该预设，新建工作区或在既有工作区开启会话。这个步骤建立具体工作实例，而不是重新创建职业模板。
4. Agent 按预设中的引导方法，逐步了解具体职责、用户身份、班级或项目、时间安排、资料整理与记忆习惯。真实资料保存在这个工作实例的范围内，不回填成所有人共享的模板。
5. Agent 根据任务需要调用已实现的规范工具，生成可校验的卡片。主人检查并点击分享；群成员通过固定小程序页面参与。成员事实经过授权校验后同步回原节点，供后续工作使用。

建议在插件的微信连接设置中提供“创建职业预设”和“我的职业预设”两个入口。创建助手本身使用包内受控引导能力，不要求用户先有一个职业预设才能创建预设。第一次只收集可复用的工作方法；选择这个预设开启工作后，再逐步收集具体班级或项目资料。该入口尚未实现，不能把当前“群任务模式”页面改个名字就当作已经交付。

例如“教师助理”是可以复用的预设；“王老师的五年级二班数学工作”才是具体工作实例。同一预设可以用于不同班级，但班级资料不能自动共用。同一个人也可以同时保有项目管理预设及其独立工作实例。

## 各层职责

| 层 | 定义和职责 | 不能承担的职责 |
| --- | --- | --- |
| 宿主适配层 | 将通用的预设、会话、工作区、工具与上下文能力映射到 DSH 原生接口；Web 和桌面端各自按真实节点身份运行 | 不修改宿主原生会话归属，不把电脑路径或显示名当作授权身份 |
| 职业预设 | 可复用的工作方法、基础提示词、引导流程、所需 skill 和工具能力声明；映射为 DSH 原生 preset | 不内嵌某位学生或客户的私有档案，不等于群任务规则包，也不自动授予权限 |
| skill | 说明何时、为什么、怎样组合现有工具，例如先收集信息、再起草、最后请主人确认 | 不是授权代码，不自行制造不存在的工具或按钮，不以说明文字绕过校验 |
| 工具与协议 | 固定参数、字段、返回结果、结构化卡片、动作、回执、幂等及失败语义；代码强制执行 | 不让 Agent 手写可执行 JavaScript、WXML、任意回调地址或伪造成功回执 |
| 任务规则包 ModePackage | 版本化的任务字段、结果字段、公开卡片映射、能力依赖与批准规则 | 不是 DSH 原生职业 preset，不创建完整职业助手，不提供不存在的成员表单或私密发布 |
| 工作实例与记忆 | 具体用户、班级、项目的配置、引导答案、计划、分析和资料引用，保留来源及版本 | 不因为相同预设、职业、文件夹名而混用另一工作区的数据；模型分析不替代真实事实 |
| 业务事实与交付 | 任务、成员参与、确认、后续提交版本、处理结果与持久交付凭据 | 不把分享 API 成功当作已阅读，不把上传成功当作电脑已持久接收 |
| 小程序交互 | 主人预览批准和原生分享；成员独立受限页面；固定组件渲染校验后的数据 | 群成员不能取得主人配对凭据、电脑私有接口或其他成员私密结果 |

## 三种记忆不能混为一谈

职业方法记忆属于预设与 skill，可以复用。具体工作记忆属于班级或项目，包括用户确认的信息、计划、时间安排和资料索引。业务事实记忆由系统保存参与、确认、提交和交付事件，有独立来源及版本；Agent 可以引用和分析，不能靠文字改写。

本轮 WorkflowRecords 已提供会话内持久计划、分析引用及逐步引导答案；它不是完整的跨会话业务资料库，也没有自动建立用户工作区文件夹。目录初始化和文件记忆需要通过宿主原生能力、明确工作区及用户权限来实现，不能默认写入全局目录。

成员填写姓名只建立“该参与者自行登记了这个名字”的事实，不直接证明其真实身份。名单认领、同名、重复认领与主人确认还需独立设计和实现。微信群能力不等于能获取完整群成员列表，也不等于可以读取群聊天历史。

## 隔离和复用

节点是隔离边界之一。同电脑 Web 和桌面端是不同节点；相同工作目录不构成互相读取任务的授权。

职业模板可以在同一授权节点复用。具体班级或项目未来可以由多个会话共同使用，但必须明确加入同一个业务工作实例，并保留各自任务来源；不能由 preset 名字、cwd 或“最近使用的群”自动推断。

本轮先实现严格的 nodeId、sessionId、sessionGeneration 绑定。跨会话加入与共享业务记忆尚未开放，因此当前不会把另一个会话的数据交给 Agent。切换任务规则包不改写旧工作记录的固定版本。未来实现工作区级共享时，应增加显式工作实例身份与加入授权，不能直接放宽现有会话过滤条件。

## 工具卡片的固定执行链

Agent 调用类型化工具，插件验证参数并保存来源，返回真实结构化卡片；小程序只渲染包内固定组件。主人批准后，插件为已经保存的操作提供短期来源凭证，云端再核对当前账号、原节点、绑定代次和具体任务来源，才允许发布或后续动作。群成员的响应由独立受限入口处理，事实与事件在同一事务提交，节点按快照和游标同步。

skill 负责教 Agent 使用这条链；preset 负责选择工作方法和所需能力；工具代码及云端负责守住链上的权限和真实状态。三者缺一不可，但不能互相代替。

创建职业预设时，可以生成职业化的工作指导和组合声明，但只能选择实际可用、受信任的工具与插件。工具参数、卡片协议、回调路由和权限检查由代码维护，不由每个职业重新生成。具体教师、项目管理者的 skill 可以不同，底层发卡、回执、隔离与交付规则仍相同。未安装或未授权的能力应明确提示，不因预设声明了能力便自动变成已启用。

## 本轮实际实现范围

新增代码包含能力目录、任务规则包草稿及版本、主人预览批准及回退、会话内工作记录、逐步引导答案、规范化公开阅读卡片、云端真实节点授权适配、任务归属与稳定参与者、事务事件、节点快照及增量同步、Agent 只读任务查询。能力目录对附件、私密结果、条件收件人和自动运行明确标为尚不可用，不生成这些功能的假入口。

仍需接续实现：职业预设创建助手和原生 preset 保存、配套 skill 的可靠安装与选择、工作实例初始化与显式跨会话加入、业务目录与记忆管理、成员登记表单与姓名认领、群任务附件接收及持久交付、私密结果和订正、授权自动化策略。这些不是换一个提示词即可完成，也不应通过宽泛放开权限来模拟。

新增代码只在研发分支验证，未部署云端、上传小程序或发布插件。本文件与本地验收记录一起维护；不得将自动化回归通过写成真机验收或全功能完成。
