# npm 短命令安装：开发检查点（未发布）

目标命令：`npx -y dsh-wechat-remote@latest`。账号为仓库维护者，npm 包名与 GitHub 仓库名一致；实际 DSH 插件仍使用 `@harness-remote/dsh-wechat-remote`，不改变 profile、节点身份或配对协议。

本检查点不是可分发的安装器。`installer/package.json` 保持 `private: true`，入口和完整宿主生命周期尚未完成，不能解除发布保护。GitHub 正式版 1.6.1 不改写、不覆盖；小程序和服务器的现有安装指引尚未切换。

## 已实现

- 安装工具通过普通 npm 依赖声明固定为 pnpm 11.22.0，走包的公开入口和 `bin`，不依赖全局 PATH、Corepack shim 或手动工具安装。
- 发现并修正 pnpm 11 `add` 不接受旧 `--no-frozen-lockfile` 参数的问题，改用其支持的配置参数。
- 抽取共用的 profile 暂存安装模块，由 DSH 原生 `dsh plugin` 初始化 profile、安装发布包、注册 bundle。私有临时 PATH 仅用于该次安装，不修改全局 npm/pnpm 或 shell 配置。
- 保留现有更新事务的包校验、空闲检查、保存、备份、重启验证及回滚；复制完整 worker 模块闭包。
- 更新标签区分兼容性、是否有适配的正式更新和能否自动安装；缺少兼容证据不等于必须更新，无更新时不显示无关工具环境错误。
- WebUI 的明确“更新并重启”按钮不再追加确认弹窗；成功后通过 DSH `connection.authenticatedUrl()` 的原生接口恢复浏览器认证。地址仅经本机受限管理接口返回，不进入公网元数据或进度日志。

## 实际证据与边界

- 完整插件 bundle、原有全部测试和 verify 通过；新增安装工具、更新动作、来源和恢复地址检查通过。
- Windows / DSH 0.1.2-rc.1 / Node 24.15：隔离全新 profile 安装 1.6.1、原生 bundle 注册、目录迁移通过；隔离 1.5.5 → 1.6.2-dev.1 暂存升级及安装后自带 pnpm 运行通过。
- macOS Intel / DSH 0.1.2-rc.1 / Node 25.9：同上两类隔离安装验证通过。
- Ubuntu x64 / DSH 0.1.1-rc.2 / Node 22.22.3：官方 pnpm 包由可信开发机传输后，隔离安装 1.6.1、原生注册及迁移通过。直接访问 npm 官方仓库发生 TLS ECONNRESET；升级候选时下载 pnpm 依赖也遇到此错误，未切换当前 profile。不能记作网络冷安装通过，未关闭 TLS 校验。
- 这些是安装原语测试，不是完整短命令、宿主自动重启、浏览器自动恢复或真机配对验收。三台原用户测试节点均未替换或重启。
- 恢复地址和迁移链接保护的新检查需纳入最终完整事务重测；先前跨机暂存验证不能代替这一验收。

## 发布前剩余工作

1. 完成短命令入口、官方 DSH 安装定位、当前 profile 判定、只选择经验证的适配正式版和完整事务调用，复用现有下载与策略模块。
2. 将宿主启动方式作为独立的生命周期适配层验证。当前 updater 仍拒绝 systemd、launchd 等服务管理方式，不能直接删掉这些保护：服务管理器可能杀死同组 worker 或自行重启旧 profile。需要经验证的独立 helper 与原服务恢复机制。
3. 验证旧 1.5.5 第一次升级的安全停机路径，不能仅凭端口猜 PID，不能丢失 DSH_HOME、profile、工作目录、启动参数和模型环境；不能把需要人工重启包装成已实现一键完成。
4. 验证网络中断、无法写入、正在执行的会话、重复点击、安装失败、重启失败、回滚和浏览器新认证地址恢复。
5. 完成 npm 包打包和干净环境短命令验收；准备真实发布内容后由维护者完成必要的 npm 发布身份验证。当前未发布、未占用 npm 包名。
6. npm 正式包发布并验证后，再同时更新小程序与云端命令白名单及两处指引，保持安装／手动升级为同一短命令。生产服务变更仍需按部署授权与回滚流程处理。
