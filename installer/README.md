# Agent远程管理助手 · DSH 插件安装器

命令行入口用于已正常停止的 DSH Web；同一个安装包也可在 Desktop 原生插件管理器中安装。

首次安装和升级使用同一个命令：

```sh
npx -y dsh-wechat-remote@latest
```

运行前请结束任务并通过原启动方式正常停止 Web；后台服务需先暂停自动重启。运行中的 Web 会被明确拒绝，安装器不会停止它、修改用户补丁或接管宿主生命周期。若原来通过原生插件管理页安装，请仍使用该入口更新，不要叠加命令行安装包。

在与 DSH 相同的系统用户下运行，需要 Node.js 22.13 或更高版本，无需另装 pnpm 或 Git。Windows CMD / PowerShell 推荐使用 `npx.cmd -y dsh-wechat-remote@latest`，不必修改脚本执行策略。使用 NPX 启动的 DSH 无需改成全局安装。

安装器保留原配置、配对和会话，不升级 DSH 本体。停止状态下通过 DSH 原生插件命令安装；成功后尝试启动 WebUI。后台服务请在确认安装完成后按原方式恢复，避免重复启动。若启动失败，查看安装日志；启动失败不会自动回退已安装插件，也不要删除数据。

安装器内置完整插件，安装内置版本不依赖 GitHub 附件下载。仍检查安装归属、包完整性和已知不兼容问题；未登记的 CPU 或 DSH 版本不等于已验证，也不会单独因为缺少记录拒绝安装。

默认使用 `web` 配置和原来的数据目录。自定义目录时保留相同的 `DSH_HOME`，或附加 `--home "数据目录"`；其他配置使用 `--profile 配置名称`。优先使用当前终端默认的 DSH；存在多份且无法确定时，请用 `--dsh-cli "DSH的lib/bin.js路径"` 明确选择。WSL、容器和其他系统用户需在对应环境执行，不能跨环境替换。

停止 Web 后可用 `--repair` 主动重装，不会自动降级。旧的更新记录、备份和锁不会被自动删除或用来恢复宿主；结果不明时先核对记录，勿重复安装。

Desktop 请在原生插件管理器中添加 `dsh-wechat-remote`，不支持 `--profile desktop`。Desktop 的一键更新仍使用宿主原生安装流程；提示待生效时，任务结束后完全退出并重新打开，无需重新配对。

另一端支持原生插件管理时，可在确认后等待空闲更新；命令行安装的 Web 只显示手工更新提示，不再提供跨端自动替换、重启与回退。未安装、已停用的另一端不会被自动安装或启用。
