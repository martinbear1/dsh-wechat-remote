# Agent远程管理助手 · DSH 插件安装器

通常在 DSH 的 **插件 → 添加插件** 输入 `dsh-wechat-remote@latest` 即可。已有安装使用插件内的检查更新，不要卸载或叠加安装。Web、Desktop 的安装包名相同。

本候选版提供 Web 保底替换升级，包括通过原生插件管理器安装、旧更新按钮不能升级的 `1.7.13`。不需要先卸载旧插件，见 [安装与更新说明](../docs/NATIVE-INSTALL.md)。本版尚未公开发布，当前公共 `@latest` 仍是 `1.7.13`。

Web 新装或保底升级使用同一行命令：

```sh
npx -y dsh-wechat-remote@latest
```

运行前请结束任务并通过原启动方式正常停止 Web；后台服务需先暂停自动重启。安装器不会强停会话或修改用户补丁。原生管理器安装与早期命令行安装都替换原有包，不添加第二份插件；新装使用标准原生包。

在与 DSH 相同的系统用户下运行，需要 Node.js 22.13 或更高版本，无需另装 pnpm 或 Git。Windows CMD / PowerShell 推荐使用 `npx.cmd -y dsh-wechat-remote@latest`，不必修改脚本执行策略。使用 NPX 启动的 DSH 无需改成全局安装。

安装器保留原配置、配对和会话，不升级 DSH 本体。停止状态下通过 DSH 原生插件命令安装；成功后尝试启动 WebUI。后台服务可加 `--no-start`，确认安装完成后由原服务启动，避免重复启动。若启动失败，查看安装日志；启动失败不会自动回退已安装插件，也不要删除数据。

安装器内置完整插件，安装内置版本不依赖 GitHub 附件下载。仍检查安装归属、包完整性和已知不兼容问题；未登记的 CPU 或 DSH 版本不等于已验证，也不会单独因为缺少记录拒绝安装。

默认使用 `web` 配置和原来的数据目录。自定义目录时保留相同的 `DSH_HOME`，或附加 `--home "数据目录"`；其他配置使用 `--profile 配置名称`。优先使用当前终端默认的 DSH；存在多份且无法确定时，请用 `--dsh-cli "DSH的lib/bin.js路径"` 明确选择。WSL、容器和其他系统用户需在对应环境执行，不能跨环境替换。

停止 Web 后可用 `--repair` 主动重装，不会自动降级。旧的更新记录、备份和锁不会被自动删除或用来恢复宿主；结果不明时先核对记录，勿重复安装。

Desktop 新装请在原生插件管理器中添加 `dsh-wechat-remote@latest`，已有安装使用插件内检查更新。本命令不安装、更新或停止 Desktop，也不支持 `--profile desktop`。提示待生效时，任务结束后完全退出并重新打开，无需重新配对。

更新仅针对你选择的节点。未安装、已停用的另一端不会被自动安装或启用。
